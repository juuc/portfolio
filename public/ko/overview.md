## 실질 산출물 5가지

### 1. 세무GPT 상용화

세무GPT를 AI 제품 개발 단계에서 프로덕션 운영 단계로 이동시켰습니다. 멤버십 권한, 결제/웹훅 처리, 평가 루프, 프롬프트 관측성, CI/CD, 운영 runbook, 도메인 전환 준비, 클라이언트 인수인계, 상용 계약 체결까지 연결했습니다.

### 2. 부톡 플랫폼 재건

CTO 전환 이후 웹, 앱, 백엔드, 데이터, 릴리스, 배포를 가로지르는 엔지니어링 실행을 맡았습니다. 중요한 결과는 “많은 레포를 만졌다”가 아니라, 취약한 플랫폼을 4인 팀이 지속적으로 배포 가능한 구조로 바꾼 것입니다.

### 3. 검색/성능 전환

공개 웹 경험을 검색엔진에 거의 보이지 않던 CSR/정적 구조에서 SSR, 동적 사이트맵, 구조화 데이터 기반으로 전환했습니다. PageSpeed는 20에서 80으로 올라갔고, 48K+ 매물 페이지가 색인 가능한 상태가 되었습니다.

### 4. 자율 프로덕션 운영

Sentry Issue 분석 봇은 프로덕션 알림을 AI 진단과 수정 PR 생성으로 연결했습니다. 에러 대응을 수동 온콜 업무가 아니라 반복 가능한 운영 파이프라인으로 바꾼 사례입니다.

### 5. 데이터 신뢰성 복구

크롤러와 백엔드 데이터 문제를 단발성 수정이 아니라 시스템 문제로 다뤘습니다. 라이프사이클 전파, 좌표 복구, preflight gate, 오케스트레이션, 모니터링을 통해 데이터 신선도와 정합성을 운영 관점에서 볼 수 있게 만들었습니다.

## 운영 방식

제가 반복해서 쓰는 패턴은 다음과 같습니다.

```text
취약한 시스템 -> 작고 안전한 단계 -> 자동 검증 -> 프로덕션 인수인계
```

AI는 그 시스템의 일부지만 목적 자체는 아닙니다. 핵심은 절제된 레버리지입니다. 아키텍처를 정하고, 작업을 충돌 없는 단계로 나누고, 에이전트가 제한된 범위에서 실행하게 한 뒤, 사람이 리뷰하고, 테스트/모니터링/롤백 경로로 프로덕션 안전성을 유지합니다.

## 현재 포지셔닝

저는 제품, 플랫폼, 실행이 겹치는 지점에서 가장 강합니다.

- 문서가 완벽하지 않은 시스템도 인수해서 구조를 파악하고 안정화
- 분산된 코드베이스를 조율 가능한 릴리스 시스템으로 전환
- AI agent를 데모가 아닌 엔지니어링 운영 레이어로 활용
- 프로토타입을 프로덕션과 상용 결과로 연결
- 공개 문서에서는 임팩트를 선명하게 보여주되 내부 운영 세부사항은 보호
