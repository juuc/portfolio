# 데이터 신뢰성 복구

## 왜 중요한가

부동산 제품은 데이터의 신선도와 정합성에 대한 신뢰에 의존합니다. 크롤러나 라이프사이클 버그는 단순한 백엔드 결함이 아니라, 사용자가 시장을 이해하는 방식에 영향을 줄 수 있습니다.

## 문제

데이터 작업은 크롤러, 백엔드 전파, 랭킹 로직, 위치 필드, 외부 공공 데이터셋에 걸쳐 있었습니다. 실패는 원인을 만든 writer와 멀리 떨어진 downstream에서 드러날 수 있었고, 단발성 수정만으로는 부족했습니다.

## 산출물

- 데이터 사고를 고립된 패치가 아니라 시스템 문제로 다뤘습니다.
- 리스크가 큰 데이터 필드에는 repository-level guard를 추가했습니다.
- 필요한 경우 오염되거나 오래된 프로덕션 데이터를 복구했습니다.
- 오케스트레이션, 모니터링, preflight check로 데이터 신선도를 보이게 만들었습니다.
- 이후 인수인계가 기억에 의존하지 않도록 운영 runbook을 문서화했습니다.

## 임팩트

프로덕션 압박 속에서도 데이터 레이어를 더 쉽게 추론할 수 있게 되었습니다. 중요한 산출물은 특정 크롤러 수정 하나가 아니라, 데이터 라이프사이클, 복구, 마이그레이션을 더 안전하게 운영하는 모델이었습니다.

## 근거

- 크롤러 복구와 좌표 정정 작업.
- 아파트 데이터 라이프사이클 전파 수정.
- 오케스트레이션 기반 배치/데이터 파이프라인 현대화.
- 백엔드 변경을 위한 마이그레이션 preflight gate.
