# 프론트엔드 모노레포

## 프로젝트 개요

부톡의 모든 클라이언트 애플리케이션을 통합하는 중앙 프론트엔드 모노레포. **2025년 11월에 생성** — 기존에 분산되어 있던 레포지토리(웹, 모바일 앱, 어드민)를 단일 코드베이스로 통합하여 크로스 레포 의존성 문제를 해결하고 공유 인프라를 가능하게 한 전략적 이니셔티브.

- **apps/web** — Next.js 공개 웹사이트 (bootalk.co.kr)
- **apps/app** — React Native 모바일 앱 컴포넌트
- **apps/admin** — 중개사 관리 대시보드
- **파트너 웹뷰**
- **packages/** — 공유 타입, API 클라이언트, 유틸리티

## 비즈니스 임팩트

### 1. 타입 안전성 캠페인 — 프로덕션 에러 근절

**문제:** 코드베이스 전반의 `any` 사용으로 런타임 에러가 조용히 발생. 사용자는 UI 깨짐과 데이터 불일치를 경험.

**해결:** 웹, 앱, 어드민 모듈 전반에 걸친 페이즈 기반 타입 마이그레이션을 주도했습니다. `any` 타입을 적절한 TypeScript 인터페이스로 체계적으로 교체했고, AI 기반 병렬 실행으로 릴리스를 흔들지 않으면서 캠페인을 계속 밀어붙였습니다.

**성과 (2025-12~2026-01 마이그레이션 당시 스냅샷이며, 2026-08-09에 재측정하지 않음):**
| 모듈 | 이전 | 이후 | 커버리지 |
|------|------|------|----------|
| App | 122개 `any` | **0개** (100% ANY-FREE) | **99.19%** |
| Admin | 246개 `any` | **~2개** (~99%, 15 PR/~20시간) | **97.87%** |
| Web | 수백 개 | **< 90개** (진행 중) | **98.84%** |

**임팩트:** 타입 관련 프로덕션 에러를 줄였고, 리팩토링 안정성을 높였으며, 이후 성능 개선과 정합성 민감 작업을 올릴 수 있는 기반을 만들었습니다.

### 2. 포괄적 테스트 커버리지 — 사용자보다 먼저 버그 포착

**문제:** 최소한의 테스트 커버리지로 리그레션이 프로덕션에서 발견됨.

**해결:** 웹과 어드민 모듈 전반에 체계적인 단위 테스트 스위트 구축. 컴포넌트 구현에 맞춘 테스트 인프라 생성.

**임팩트:** 리팩토링 과정의 리그레션을 조기에 잡았고, 반복적인 크로스 표면 변경을 작은 팀도 배포할 수 있게 만들었습니다.

### 3. Sentry 에러 모니터링 — 선제적 프로덕션 안정화

**문제:** 프로덕션 에러가 보이지 않아 사용자 불만을 통해서만 이슈를 인지.

**해결:** 모노레포 전 앱에 Sentry 통합. 에러 심각도 분류 (크리티컬 vs. 노이즈), Cognito 토큰 만료 처리, OTA 에러 억제, 네트워크 단절 가드 추가.

**임팩트:** 프로덕션 이슈 대응이 사후 소방에서 규율 있는 인시던트→수정 워크플로우로 바뀌었습니다.

### 4. GEO — AI 검색엔진 최적화

**문제:** 부톡 콘텐츠가 AI 검색엔진(ChatGPT, Perplexity, Gemini)에서 검색되지 않음.

**해결:** 구조화 데이터 스키마(JSON-LD)와 AI 크롤러 지시어를 추가하여 Generative Engine Optimization 구현.

**임팩트:** 기존 검색뿐 아니라 AI 생성형 검색 답변에서도 제품이 노출될 가능성을 높였습니다.

### 5. 쿠폰 시스템 — 매출 & 사용자 참여

**문제:** 카카오 플러스친구 채널을 통한 사용자 참여 및 전환을 위한 프로모션 메커니즘 필요.

**해결:** 복비 50% 할인 쿠폰 시스템 엔드투엔드 구축 — 랜딩 페이지, 코드 입력, 상태 배지, 배너/모달을 웹과 앱 모두에 구현.

**임팩트:** 마케팅 캠페인과 실제 제품 전환을 연결하는 재사용 가능한 프로모션 표면을 만들었습니다.

### 6. 파트너 플랫폼 확장

**문제:** 비즈니스 파트너십에 전용 웹뷰 애플리케이션이 필요했습니다.

**해결:** 독립 프로젝트를 모노레포로 통합하고, 필요한 업그레이드를 공유 인프라 안에서 함께 처리했습니다.

**임팩트:** 유지보수 부담을 줄였고, 파트너 표면까지 공유 인프라의 혜택을 확장했습니다.

### 7. 웹 성능 에픽 — PageSpeed 20점 → 80점 (4배 향상)

**문제:** bootalk.co.kr이 [pagespeed.web.dev](https://pagespeed.web.dev)에서 ~20점으로 SEO, 사용자 이탈, 구글 Search Console 순위에 심각한 영향.

**해결:** SSR 워터폴 제거, LCP 개선, 무거운 SDK lazy load, 번들 축소, 렌더링 경로 정리를 묶은 다단계 성능 캠페인을 실행했습니다.

**임팩트:** PageSpeed 점수는 **[20 -> 80](https://pagespeed.web.dev/analysis/https-bootalk-co-kr/4jic9i7it6?form_factor=desktop)**으로 올라갔습니다. 공개 웹은 더 잘 발견되고, 더 빨라졌고, 더 안전하게 계속 개선할 수 있는 표면이 됐습니다.

### 8. 데이터 정합성, 프로덕션 폴리시, 릴리스 가드

**문제:** 모노레포가 안정화된 뒤에는 속도보다 정합성과 릴리스 신뢰도가 더 큰 리스크가 됐습니다. 여러 표면을 함께 건드리는 변경에서 회귀를 막아야 했습니다.

**해결:** 공유 프론트엔드 운영 레이어를 활용해 전월세 전환 UI 변경, 데이터 정합성 체크 포인트, 세무GPT 프로덕션 완성도 개선, CI/배포 가드 강화를 함께 밀었습니다.

**임팩트:** 모노레포는 단순 통합 저장소가 아니라, 정합성 민감 제품 작업과 더 안전한 릴리스를 전달하는 운영 표면이 됐습니다.

### 9. 커스텀 E2E 테스트 프레임워크 — 기성 도구로 테스트할 수 없는 영역

**문제:** 앱이 웹뷰를 광범위하게 사용(계산기, 기업 제휴 할인, 파트너 페이지). Detox, Maestro, Appium 같은 기성 모바일 테스트 도구는 웹뷰 DOM을 검사할 수 없어 — 네이티브 UI만 볼 수 있음. 핵심 사용자 플로우가 테스트 불가 상태.

**해결:** 듀얼 채널 아키텍처 기반 이벤트 드리븐 E2E 프레임워크를 직접 구축 (~3,600줄 TypeScript):

```
App (React Native)              Engine (Node.js)
──────────────────              ──────────────────
console.log(E2E_DATA:*)  ──>   LogcatStream  ──>  AssertionWaiter
console.log(E2E_SCREEN:*) ──>  LogcatStream  ──>  Precondition checks
WebView CDP events        ──>   CDPClient     ──>  AssertionWaiter
```

**핵심 아키텍처 결정:**

- **이벤트 드리븐 어서션** — 고정 sleep 폴링 대신 앱이 방출하는 logcat 시그널(`E2E_DATA:LoginComplete`)에 반응. 더 빠르고 안정적.
- **듀얼 채널 테스팅** — 네이티브 UI용 ADB `uiautomator dump` + 웹뷰 DOM용 Chrome DevTools Protocol, CDP→ADB 손상 문제에 대한 복구 패턴 포함.
- **TapHint 프로토콜** — 앱이 자체 엘리먼트 좌표를 보고(`E2E_DATA:TapHint:{testId}:{cx}:{cy}`), 지도 마커 같은 동적 배치 엘리먼트의 ADB bounds 불일치 문제 해결.
- **선언적 YAML 플로우** — 19개 플로우, 232개 테스트 스텝. TypeScript 지식 없이도 비개발자가 테스트 시나리오 작성 가능.
- **프로덕션 오버헤드 제로** — 모든 마커가 `if (__DEV__)` 래핑, 프로덕션 빌드에서 제거.

**임팩트:** 로그인, 매칭, 채팅, 보안, 지도, 상태 관리, 앱 안정성, 웹뷰 인터랙션, 인증 라이프사이클, AI 기능을 커버하는 19개 플로우를 확보했습니다. 초기 실행에서 유닛 테스트로 놓친 실제 API 마이그레이션 버그도 포착했습니다.
